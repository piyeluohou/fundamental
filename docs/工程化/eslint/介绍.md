ESLint 的规则执行原理本质上可以理解为：

ESLint 读取配置 → 解析代码生成 AST → 遍历 AST 节点 → 运行规则插件 → 收集问题 → 格式化输出结果

它不是简单的“正则扫描代码”，而是基于 AST（抽象语法树） 做静态分析。

下面从执行流程到底层原理讲一下。

ESLint规则执行原理？

回答：
ESLint 本质是基于 AST 的静态代码分析工具。执行时首先加载配置文件，解析 plugins、extends 和 rules，然后通过 parser 将源码转换成 AST。ESLint 使用 visitor 模式遍历 AST 节点，每个 rule 通过 create 方法返回节点监听函数，当遍历到对应节点时触发规则逻辑，通过 context.report 收集错误信息，最后经过 formatter 输出检查结果。
