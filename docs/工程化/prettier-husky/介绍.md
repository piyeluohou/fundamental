|                  | ESLint             | Prettier        |
| ---------------- | ------------------ | --------------- |
| 定位             | 静态代码检查工具   | 代码格式化工具  |
| 关注             | 代码是否正确、规范 | 代码长什么样    |
| 是否理解代码逻辑 | ✅ AST分析         | ❌ 主要关注格式 |
| 是否修改代码     | 可以修复部分问题   | 专门修改格式    |
| 典型用途         | 找 bug、规范代码   | 自动排版        |
| 配置复杂度       | 高                 | 低              |

ESLint负责质量，Prettier负责格式。

ESLint是基于AST的代码质量检查工具，主要发现潜在错误和不规范代码，比如未使用变量、类型错误、React Hooks规则等；Prettier是代码格式化工具，只负责统一代码风格，比如缩进、换行、引号和分号。实际项目中通常使用Prettier负责格式，ESLint负责质量检查，并通过eslint-config-prettier解决规则冲突。

Husky解决：
把hook配置放到项目
Husky 是一个 Git Hook 管理工具，它可以在 Git 的生命周期阶段自动执行脚本。例如在 commit 前执行 ESLint、Prettier、单元测试，在 commit-msg 阶段校验提交信息规范。它主要用于保证团队代码质量，避免不符合规范的代码进入仓库。实际项目中通常结合 lint-staged 使用，只检查 git 暂存区修改的文件，提高执行效率。

为什么需要Husky？
回答：
防止开发者绕过本地规范提交问题代码，把代码质量检查提前到commit阶段。
