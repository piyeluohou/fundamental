# 作用

当组件渲染完成后，如果我关心的数据发生了变化，就执行相应的副作用逻辑。
这里的副作用（Side Effect），就是指影响 React 组件渲染之外的事情。
如DOM 操作，定时器

# 依赖

不传依赖数组，每次提交更新后都会执行
传入空依赖数组 [] 通常只在组件挂载后执行一次 - 初始化某些外部资源。- 页面首次加载时获取数据。- 建立 WebSocket 连接。- 注册某些事件监听。
传入具体依赖 [count] 首次挂载后执行，之后依赖变化时执行

Effect 内部使用的、来自组件作用域的响应式值，通常都应该纳入依赖数组。

useEffect 和 useLayoutEffect
两者都用于处理副作用，但执行时机不同。
useEffect
通常在浏览器绘制之后
适合网络请求、订阅、定时器等不需要阻塞页面绘制的操作。

useLayoutEffect
DOM 更新后、浏览器绘制之前
适合需要同步读取 DOM 布局并立即调整页面的场景。
useEffect 是异步调度的副作用，通常在浏览器绘制后执行；useLayoutEffect 则在 DOM 更新后、浏览器绘制前同步执行，适用于布局测量和同步调整。一般优先使用 useEffect，只有确实需要避免视觉闪烁时才考虑 useLayoutEffect。

StrictMode 的主要目的是帮助发现 Effect 是否正确清理副作用，以及组件是否能正确应对重新挂载。

# 问题：自定义 Hook 和普通工具函数有什么区别？

可以这样回答：

自定义 Hook 本质上也是 JavaScript 函数，但它遵循 React Hooks 的调用规则，可以在函数组件或其他自定义 Hook 中调用 useState、useEffect 等 React Hooks，从而复用组件逻辑和状态相关行为。

普通工具函数只是普通 JavaScript 函数，不能直接调用 React Hooks，因为它不处于 React 的组件渲染上下文中。

自定义 Hook 本身不会创建独立的 React 组件实例，也不会创建独立的 Fiber。它内部调用的 Hooks，其状态仍然归属于调用它的函数组件 Fiber。

因此，两个组件即使调用同一个自定义 Hook，也会拥有各自独立的 State。自定义 Hook 复用的是逻辑，而不是自动共享状态。

如果需要跨组件共享状态，需要借助 Context、状态提升或者 MobX、Zustand 等状态管理方案。

面试加分点： 自定义 Hook 的核心价值不是减少代码行数，而是复用有状态的逻辑，同时保持组件之间的状态隔离。
